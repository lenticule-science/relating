# 2026-06-15

## Addendum: The Package Is Relating Now

The package name moved from `@emsenn/relationality` to `@emsenn/relating`.
That is not meant as a coat of paint. "Relating" names the category we are
trying to implement: a base object `Mark`, a base carrier `Utterance =
(Token, Claim)`, and a base morphism `articulate`.

I also started a migration note at
`dev/docs/explanations/category-of-relating.md`. The point of that document is
to stop treating `algebra`, `topology`, `logic`, `geometry`, and `analysis` as
software buckets. The target allocation follows the mathematical pressure the
code has been revealing: current algebra wants to become topology, current
topology wants to split toward logic and geometry, and current geometry wants
to become analysis. Symbols should move only when their domain, codomain, and
normalization path back to Mark/Utterance/articulate are clear.

The first nested surface is now on disk:

```text
articulating/
  predicating/
    positing/
      settling/
```

Those files are barrels over the older implementation modules for now. That is
intentional. The package can expose the mathematically correct containment
chain before every implementation file has been moved, and tests can keep the
old and new surfaces honest during the migration.

I also wrote down the general packaging rule set at
`dev/docs/guides/category-theoretic-node-packaging.md`. The short version:
packages name categories, modules name objects or subcategories, nesting means
mathematical containment, functions are morphisms, boundary modules are not
ontology, and file moves require domain/codomain evidence.

The test suite now checks that law at the package boundary. The export map must
name `@emsenn/relating`, expose the nested articulating chain and script
surface, and keep `./topology/internal` out of the public contract.

## Relating, Pipes, and the Shape of a Mark

There is an old Unix feeling I keep wanting from `@emsenn/relating`: a
program prints something another program can read, and the interesting part is
not the plumbing. You should be able to run a command, pipe its result into a
read, feed that read back into a relation, and not stop every six inches to
invent another local object protocol.

That is the practical software pressure behind the current package cleanup.
Shell users want pipes. HTTP/OpenAPI users want request and response bodies
that chain. MCP users want tool results that can become tool inputs. TypeScript
users want the same callable shape without spawning a process. Those are not
four API designs. They are four transports asking for the same morphism.

The shape I am moving the package toward is:

```text
(action, token, ?claim) -> settlement
```

The token and claim arrive at a boundary as documents. The relational core sees
Marks, Tokens, Claims, Utterances, predication carriers, and settled readings.
The default wire form is EAVT/Datom JSONL because it is simple enough for shell
composition and structured enough for API and MCP adapters.

An EAVT row may be spelled as a tuple:

```json
["token", "attribute", "value", "time"]
```

or as an object:

```json
{"e": "token", "a": "attribute", "v": "value", "t": "time"}
```

At the boundary this becomes an utterance whose token is `e` and whose claim is
the richer record `{a,v,t}`. A settled read emits EAVT again, but the value slot
is no longer pretending to be a plain object coordinate:

```json
["subject", "predicate", {"object": "object", "charge": "potential"}, "time"]
```

That little nested value is doing real work. It says: this is not just an
asserted coordinate; this is a read, a settlement, something derived by the
relational descent. If a caller asks for Datom, the fifth slot carries that
reading.

The executable may stamp time when the user does not supply one. That is its
job as a process at the I/O boundary. The importable library code still does
not get to read the clock behind your back.

## The One Arbitrary Thing

The package drifted in a familiar TypeScript way: useful code slowly forgot
where arbitrary data was allowed to live.

In this mathematics, `Mark` is the arbitrary carrier. A Mark may wrap anything.
That is the point, not an inconvenience to normalize away. The core must not
open arbitrary Mark payloads and decide that they are JSON, strings, records,
subjects, predicates, objects, or anything else. It may carry them. It may
articulate them. It may induce relational structure around them. It may not
secretly install JavaScript's value theory as the package's ontology.

So the rule is now explicit:

- `Mark` is arbitrary.
- Tokens and Claims carry Marks.
- An Utterance is the admission shape, `(Token, Claim)`.
- Subject, predicate, object, and charge are derived readings.
- Representation boundaries may inspect payloads only to prove that the chosen
  representation can carry them.

This means old conveniences had to go. There is no public Mark equality helper
that compares arbitrary payloads. Token and claim identity remain carrier
judgments, but we do not decide the equality of all possible Mark contents by
accidentally calling into JavaScript.

It also means JSON is not the Mark carrier. JSON is a boundary carrier. HTML is
a boundary carrier. TOML and Turtle are boundary carriers. EAVT is a boundary
carrier. A Mark can be serialized through one of those only after the boundary
has proved that this particular payload inhabits that representation.

## Frege Is Hiding in the Pipes

The categorical part matters here because otherwise this all looks like
ordinary CLI cleanup.

Admission is not "declare subject, predicate, object." Admission is an
utterance. Predicating happens after articulation. The predication category
opens a value-free cell set, the Fregean unsaturated place where the predicate
has not been collapsed into a data field. Charge is later, at positing and
settling. That is why directly injecting charge, polarity, denial, or a
subject-predicate-object declaration into core is the wrong move.

The research corpus says the same thing in its own language: the predicating
category carries the value-free cell set, `Phi = E x Pi x E`, and a cellular
fiber. Values enter later. The code should make that invariant hard to violate.

The user-facing consequence is almost boring:

```sh
eval-relation --action=scripts.settle log.jsonl
eval-relation --action=scripts.read settled.eavt
eval-relation --action=scripts.compare observed.eavt --claim=control.eavt
```

But the reason that works is not boring. The command line is not an ad hoc
mini-app. It is an executable view of a finite morphism registry.

## The Script Surface

The package now has a public script surface:

```ts
evalRelation
scriptActions
scriptMorphisms
```

Every script morphism has the same shape:

```ts
(tokenDocument, claimDocument, options) => BoundaryDocument
```

`BoundaryDocument` is a deliberately plain name. In TypeScript it is a string,
but this is not a claim that Marks are strings. It means the executable,
HTTP adapter, MCP adapter, or caller has decoded a POSIX/API/MCP byte stream
into a runtime document. It is boundary material, not ontology.

The root package import now exposes only this callable script morphism surface.
That was an intentional break. Previously the root also exported broad
namespaces like `algebra` and `topology`, which meant TypeScript importers got a
richer default surface than shell or MCP users. That was convenient, but it was
the wrong default.

The categorical surfaces still exist. They are explicit subpaths:

```ts
import { mark, utterance } from "@emsenn/relating/algebra";
import { induce } from "@emsenn/relating/topology";
import { parseLines, toEavt } from "@emsenn/relating/codecs/resource";
```

The compromise is clean:

- root import: callable morphisms, same conceptual surface as shell/API/MCP;
- subpath imports: categorical carriers, codomains, extrema, and representation
  boundaries.

That keeps relating a mathematical library without making the root a
namespace junk drawer.

## Witnesses, Not Casts

Most of the code cleanup has been one pattern repeated at different scales:
remove "trust me" assertions and replace them with witnesses.

Raw `JSON.parse` now belongs inside the JSON resource codec. After parsing, the
package proves a value is a `JsonValue`. JSON objects are plain string-keyed
records, not arbitrary JavaScript instances that happen to have enumerable
properties. The JSON codec now exports `JsonRecord` and `isJsonRecord`, and
script/evaluate/datom code uses that shared witness instead of local record
guesses.

Finite vocabularies are witnessed too. `--order`, `--bound`, `--charge`, and
wire charge readings are no longer cast from strings into mathematical names.
They pass through small parsers that know the finite carrier. A malformed
charge like `"maybe"` fails at the boundary instead of becoming an impossible
member of Belnap's FOUR through TypeScript optimism.

The same cleanup touched the utterance log decoder. A JSON value is not already
an utterance log. It becomes one only after the `meme-topology.utteranceLog`
shape is witnessed and each encoded `(token, claim)` entry is present.

TOML got its own version of this: dotted table traversal now uses helper
witnesses for tables and arrays of tables instead of mutating through asserted
shapes.

Even stdin had a tiny version of the problem. The shell helper no longer says
`chunk as Buffer`; it constructs bytes from the chunk Node actually gives it.
Small thing, same principle.

## HTML and Other Boundary Manners

The HTML projector had a classic JavaScript leak: object-valued witness marks
could render as `[object Object]`. That is not a representation; it is an
accident.

Object and array values now render through canonical JSON when they are
HTML-projectable. Opaque witness marks still fail before projection. Packet
identity canonicalizes frontier terms deterministically, so object key order
does not leak into identity.

The EAVT/Datom codec follows the same rule. Object-spelled EAVT rows must carry
all four coordinates. A row missing `t` or `v` is not a partial witness; it is
not an EAVT. Writing EAVT from a charged cell emits one row per present-side
witness and refuses a non-JSON time witness instead of casting arbitrary Marks.

Again: the core can carry arbitrary Marks. The boundary cannot lie about what
it can serialize.

## What Changed in the Public Story

The public story is now easier to explain:

```ts
import { evalRelation, scriptActions, scriptMorphisms } from "@emsenn/relating";
```

That is the same callable surface the bins wrap:

```sh
eval-relation
relating-read
relating-compare
```

The scripts do no filesystem, stdin/stdout, fetch, or clock I/O themselves.
The executable wrappers own those effects. The pure callable surface receives
already-read boundary documents and an explicit timestamp value. When the
executable supplies a default timestamp, that default is created at the
executable boundary.

The export map still matters. It is not being collapsed into "just scripts."
The exported algebra, topology, logic, geometry, analysis, holography, and
codec subpaths should name real carrier surfaces: domains, codomains, extrema,
apex objects, morphisms, and representation boundaries. The audit is not done,
but the criterion is now written down.

## Still Open

There is still a lot to do.

The export map needs a term-by-term categorical audit. If a subpath names a
domain, codomain, extremum, apex, morphism, or representation boundary, it can
stay public. If it is merely convenient implementation furniture, it should not
be in the public map.

There are also historical subject/predicate/object names in codecs and
readings. Some are correct because they are derived readings at a boundary.
Some may still be fossils from an older, flatter model. Those need to be
checked against the predication category, not against taste.

Downstream, the same discipline needs to reach the web package, agents, games,
and computers: no free JavaScript data sneaking in as relation; no bad
injections; no transport format pretending to be ontology.

For now the package is closer to the shape I want: arbitrary data enters as a
Mark, functions converge toward morphisms over token and optional claim, EAVT
is the default pipeable boundary, and the root import no longer gives
TypeScript users a private shortcut around the script surface.
